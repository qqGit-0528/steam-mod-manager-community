# 背景与目标

将当前可运行配置的 Mod 文件、声明版本、启停、顺序和 CK3 版本带到另一套环境。

## 1. 范围与非目标

在运行配置页导出、导入用户选定的本地快照包。使用原有快照格式与校验，启用项保留文件，禁用项保留清单记录。独立恢复为新配置，应用到启动器仍由用户操作。

## 2. 需求与验收条件

| ID | 给定 | 当 | 则 |
| --- | --- | --- | --- |
| AC-01 | 有效配置和可用文件 | 导出 | 本地快照包保留顺序、启停和已启用 Mod 的文件及描述哈希 |
| AC-02 | 同版本 CK3 与有效包 | 预览并确认 | 校验完整性，恢复本地副本并保存独立配置 |
| AC-03 | 版本不符、内容缺失、篡改、取消或写入失败 | 导入 | 显示失败原因且保留现有配置、Mod 和工坊数据 |
| AC-04 | 两份隔离环境 | 导出并导入 | 核对哈希、顺序和启停，验证启动器应用路径 |

## 3. 责任模块与实现步骤

Ck3PlaysetSnapshotStore 复用快照采集与恢复。ZIP 流式封装到选定路径的相邻临时文件，再发布。导入使用本地 Mod 目录暂存，验证后直接发布副本，不在应用数据另存整份快照。WorkspaceService 保存配置，失败回滚本次副本。

## 4. 契约、依赖与兼容性

文件扩展名 .ck3pack，内部为 ZIP 和原快照 v1 清单。以包中实际携带的文件恢复。已安装的禁用项文件与 CK3 本体不随包分发。旧快照、旧 JSON 清单和已有播放集保持可用。

## 5. 测试策略

覆盖 ZIP 路径约束、内容篡改、不同游戏版本、保存失败、导入导出与受控实机。按 [协作规范](../CONTRIBUTING.md#4-必须完成的检查) 执行门禁。

## 6. 审查与执行结果

AC-01 至 AC-04 通过。跨两个工作区核对目录内容、空目录、内层 ZIP 字节、原声明版本、启停和加载顺序。错误 CK3 版本、篡改的等长文件及配置保存失败均未留本次导入文件。应用后从隔离的官方启动器 SQLite 读回启用顺序。包导入只保留一份本地内容，恢复副本可以从本地库单独删除。

隔离 CK3 1.20.0.4 实机：来源用文件夹安装 A、ZIP 安装 B，导出 A→禁用项→B，随后模拟修改来源 B。接收端两份文件 SHA-256 与导出时一致，读回启动器顺序 A→B。根据读回结果生成隔离启动清单，真实游戏进入主菜单，解析日志只记录 B 的测试标记。测试游戏已退出，复查无 CK3 进程。

macOS arm64 执行还原、Release 构建、619 项全量测试和差异检查。截图和证据在本地 `artifacts/batch3/`。
