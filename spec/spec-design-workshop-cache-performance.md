# 背景与目标

列表强制刷新重复回写相同修订。对象缓存首次读取等待全量过期校验，封面热命中为桌面解码复制整图。

## 1. 范围与验收

| ID | 给定 | 当 | 则 |
| --- | --- | --- | --- |
| AC-01 | 已缓存完整正文或列表摘要 | 列表返回相同或更旧修订 | 保留现有详情及采集时间。新修订仍会使旧完整正文失效。 |
| AC-02 | 元数据缓存已接近容量上限 | 新实例首次读取 | 预算内无需遍历解析全目录正文。容量约束、目标记录过期和损坏检查继续生效。 |
| AC-03 | 桌面只需解码缓存封面 | 命中内存缓存 | 可使用只读流，避免整图复制。原有字节数组调用仍得到独立可修改副本。 |

## 2. 职责与兼容

Application 判断列表修订变化，Infrastructure 维护缓存容量和过期并提供只读封面数据，Desktop 继续独立解码与释放位图。沿用工坊缓存磁盘格式、刷新通知和 HTTP 验证语义。

## 3. 验证

覆盖修订、过期、缓存预算、只读访问和数组隔离。重跑原有离线负载及 Release 全量测试。 [协作规范](../CONTRIBUTING.md#4-必须完成的检查)

## 4. 执行结果

- AC-01 列表返回相同修订时保留详情和采集时间，遇到新修订仍替换旧内容。30 个已有详情的强制刷新从 30 次详情写入降为 0 次，P50 为 1.64–1.78 ms。
- AC-02 首次读在预算内只验证目标，显式维护仍清理过期记录。64 条详情时首次读取 P50 约 0.31 ms。
- AC-03 只读封面流不暴露底层数组。2 MiB 封面热命中使用只读流分配 712 B，数组接口仍保持隔离。
- macOS arm64 .NET 10.0.403 下完成还原、Release 构建、581 项全量回归与差异检查。真实网络、图片解码性能和长期内存未采样。

[性能基线](../docs/download-cache-search-test-report.md)

## 5. 列表与详情按需读取

搜索热命中、冷查询、强制刷新和失败回退均只读取或写入页缓存，列表使用页中的摘要。先前已确认不可用的项可继续通过内存状态排除。用户打开详情时，使用该项的列表修订判断本地详情是否仍可用，缺失、失效或显式刷新时再查 Steam。搜索路径的详情读取和写入次数均应为 0。

Release 回归共 584 项通过。测试让详情缓存拒绝任何读写，验证冷查询、热命中、强制刷新和失败回退均能完成。保留详情点击时的缓存复用和新修订检查。桌面沿用已打开详情在内存中记录的兼容标签，列表构建时无需读取正文。页缓存维护按文件容量淘汰，详情过期清理由详情写入或显式维护执行。
