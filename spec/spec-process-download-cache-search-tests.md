# 背景与目标

执行当前工作区的完整自动化回归，梳理下载、缓存和工坊搜索的单元测试覆盖。使用可重复的离线样本定位可疑耗时、分配和规模放大，整理一份中文报告。

## 1. 范围与非目标

覆盖下载去重、取消、历史读取与安装校验，工坊列表解析、过滤、请求合并与缓存，以及封面缓存的磁盘读取和维护。全套测试也执行现有临时文件、桥接替身和 Avalonia 无窗口测试，报告单独标注其层级。本轮以诊断为目标，保留当前产品行为。测试使用替身或临时文件。

## 2. 需求与验收条件

| ID | 给定 | 当 | 则 |
| --- | --- | --- | --- |
| AC-01 | 当前工作区与既有测试 | 执行完整 Release 回归 | 记录实际通过、失败和跳过数量，并保存用例结果。 |
| AC-02 | 下载、缓存和搜索现有用例 | 分析较慢的测试 | 区分夹具等待、冷启动和产品路径耗时，列出覆盖与缺口。 |
| AC-03 | 可重复的离线负载 | 比较热缓存、冷路径及不同规模 | 保存原始样本、统计口径和适用范围，对可疑结果复测并定位代码。 |
| AC-04 | 回归与测量完成 | 出具汇总 | 报告可复现异常、风险ok和未验证项，给出可定位的证据。 |

## 3. 责任模块与实施

沿用下载服务、工坊服务、Steam 网页适配器和缓存存储。性能探针使用 Release、固定夹具、临时文件与替身，不纳入时限门禁。首轮筛选后，只有可重复的路径差异、规模放大或稳态额外工作标为候选异常。

## 4. 契约与兼容性

测试和采样沿用现有入口及契约。结果可用于同机回归比较，真实 Steam 传输速率、长时间 RSS 走势和其他平台需要单独验证。

## 5. 验证命令

执行解决方案还原、Release 构建、全量测试和差异检查。保留 TRX。对现有用例不能隔离的热路径，追加本地探针并记录调用与夹具。
