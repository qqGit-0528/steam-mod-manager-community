# 背景与目标

大型历史目录加载时反序列化所有任务。长会话保留每个终态任务，进度通知也需要扫描整个任务列表。

## 1. 范围与验收

| ID | 给定 | 当 | 则 |
| --- | --- | --- | --- |
| AC-01 | 历史包含数千条任务 | 读取下载历史 | 仍按 JSON 更新时间返回最近 100 条，常规新记录无需全量解码。旧记录、无效文件、重启与并发删除继续处理。 |
| AC-02 | 会话已结束超过 100 个不同任务 | 收到终态通知 | 只保留最近 100 个终态任务和界面卡片，活动及收尾中的任务均保留。通知按任务 ID 核验。 |
| AC-03 | 活跃任务、最近历史或跨实例物品锁仍在使用 | 点击下载、重试或移除 | 沿用去重、更新和删除语义。已淘汰的卡片不因迟到通知恢复。历史读取与会话淘汰不删除安装内容。 |

## 2. 职责与兼容

Infrastructure 仍以每条任务的原子 JSON 为准。新记录可附带可排序的文件时间上界，读取时只打开可能进入最近 100 条的记录。原有路径与 JSON 可直接读取，存量历史无需批量迁移。旧记录以文件路径、大小和时间信息核验同一实例中的最近历史缓存。新记录采用 `.ordered.json` 文件名标记排序上界，旧版程序按旧文件名定位的单条删除由当前版本处理。Application 限制内存中的终态任务和历史索引，Desktop 同步限制终态卡片。活动任务维持物品锁与原有队列。

## 3. 验证

补测混合历史顺序、缺失和损坏、会话上限、过期通知、旧任务重新检查以及 active 锁。用原有离线探针比较历史与通知查询。全量运行 Release 门禁。 [协作规范](../CONTRIBUTING.md#4-必须完成的检查)

## 4. 执行结果

- AC-01 通过混合新旧文件、损坏文件、跨实例更新和删除回归。两轮 5,000 条新历史 P50 为 11.76–13.11 ms。5,000 条旧历史首次为 71.15–73.09 ms，重复读取为 10.68–11.03 ms。
- AC-02 完成 1,000 个不同 Mod 后保留 100 个终态任务。桌面回归验证活跃任务在满额时仍显示，进入终态后淘汰最早卡片。
- AC-03 同一活动任务的 100 个追加并发请求均复用一个任务。已安装复用、跨实例物品锁、历史删除与迟到事件的既有回归继续通过。
- macOS arm64 .NET 10.0.403 下完成还原、Release 构建、581 项全量回归与差异检查。真实 Steam 与长期 RSS 待验证。

## 5. 本地任务身份与实际删除

- Steam 任务以「游戏 App ID + 工坊 Mod ID」在当前本地数据目录核对。保留原任务 GUID，重启、历史窗口淘汰或修订更新后再次发起仍可复用。只在首次创建或已主动删除记录后生成新 GUID。
- 应用服务在持有现有跨实例物品锁后完成查找，再发布最终任务身份和写入记录。已有 JSON 是权威数据，已知任务按 GUID 快速核验，未命中时在当前游戏目录寻找旧记录。旧版应用自管任务仍独立处理。
- 下载卡片移除与磁盘历史删除绑定。文件系统拒绝删除时保留卡片并提示失败。成功后重启也不再出现记录。仅移除任务记录，已安装内容和订阅由独立入口管理。
- 验证历史窗口之外的身份复用、同 ID 跨游戏隔离、并发与失败路径、权限恢复后重试。多游戏历史窗口显示问题按用户决定保留。

本次在 macOS arm64 上完成还原、Release 构建和 584 项全量回归。测试用旧格式任务及 101 条较新的同游戏历史验证重启后复用，同工坊 ID 的另一游戏记录保留。模拟磁盘拒绝删除后，卡片和历史仍在，恢复权限重试成功。旧副本清理还核对更新时间，避免删除刚被另一实例写入的任务。四个桌面专项各复跑五轮通过。真实 Steam 传输未复测。
