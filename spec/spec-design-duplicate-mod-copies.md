# 背景与目标

本地库可能同时发现 Steam 与本地旧版。将同项目的不同安装关联，让用户按来源和版本选择。

## 1. 范围与非目标

各游戏现有本地库和运行配置选择器。保留原安装、配置身份和删除流程。

## 2. 需求与验收条件

| ID | 给定 | 当 | 则 |
| --- | --- | --- | --- |
| AC-01 | 同工坊 ID 的可用安装分处不同路径 | 本地扫描被接受 | 各安装显示同工坊副本标记，可查看相关版本、来源和路径 |
| AC-02 | 同名的不同工坊 ID、无工坊 ID 或同路径包装 | 计算提示 | 已知不同 ID 不互认，缺失身份时可提示疑似，同路径不重复 |
| AC-03 | 某副本卸载或扫描已过期 | 接收刷新 | 当前结果更新，迟到结果无法复活已移除的提示 |

## 3. 责任模块与实现步骤

Application 从已接受的工作区快照索引安装。Desktop 在本地列表显示副本标记、悬浮详情，在配置选择器区分来源、版本和路径。信息随现有行投影更新。

## 4. 契约、依赖与兼容性

无需数据迁移，沿用工坊 ID、管理来源和安装 ID。名称匹配去首尾空白且忽略大小写。路径沿用本地库平台规则。

## 5. 测试策略

使用本地库夹具验证三项验收，桌面夹具核对标记与列表。门禁见 [协作规范](../CONTRIBUTING.md#4-必须完成的检查)。

## 6. 审查与执行结果

AC-01 至 AC-03 通过。本地库用例覆盖不同路径、同路径包装、缺失安装、不同工坊 ID、无 ID 同名以及迟到扫描。桌面渲染验证两行提示和来源、版本、路径详情，刷新后标签消失。用临时夹具模拟安装移除，未调用 Steam 退订。

macOS arm64 执行解决方案还原、Release 构建、595 项全量测试及 `git diff --check`。无窗口截图和测试报告保存在本地 `artifacts/batch1/`。
