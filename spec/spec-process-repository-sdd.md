# 背景与目标

依据用户提供的[飞书参考](https://rcnod151qz2v.feishu.cn/wiki/Mr5ew13KPiJ55pkjQ7LcLG7bncp)，将需求澄清、实施、审查和验收接入仓库现有流程。

## 1. 范围与非目标

整理开发入口、架构约定、导航、中文技能、软件规格及一项构建检查。对两项已开发的功能补录规格。应用行为、依赖和现有 CI 工作流文件在本次范围外。

## 2. 需求与验收条件

| ID | 给定 | 当 | 则 |
| --- | --- | --- | --- |
| AC-01 | 协作者进入仓库 | 从 `AGENTS.md` 开工 | 可定位中文规范、当前责任模块、测试入口和验证命令。 |
| AC-02 | 独立变更进入实施与审查 | 使用模板和 PR 入口 | 验收条件、实现边界和证据引用同一份规格。下载和安装删除各有一份记录。 |
| AC-03 | 产品工程新增不允许的项目引用 | 执行构建 | 在解析引用前报 `SMM001`。当前允许的引用及既有测试继续通过。 |

## 3. 责任模块与实施

维护 [AGENTS.md](../AGENTS.md) 作为导航，架构与数据归属集中在[架构约定](../docs/architecture.md#架构约定)。通用检查命令沿用[协作规范](../CONTRIBUTING.md#4-必须完成的检查)。[构建检查](../Directory.Build.targets)读取经 MSBuild 求值的项目引用，现有三平台工作流通过既有构建步骤执行它。

## 4. 契约与边界

构建新增禁止引用的错误码 `SMM001`。文件所有权、层内调用、真实 Steam 行为、公开契约影响和验收口径由相应测试与人工审查确认。

## 5. 测试策略

检查新增及修改文档中的本地链接、标题锚点和技能格式。使用临时工程分别构造允许与禁止的引用，通过正常构建验证检查的生效位置。运行解决方案还原、Release 构建、全部测试和差异检查。

## 6. 审查与执行结果

2026-11-07 在 macOS arm64 验收。

| 验收 | 实际执行与结果 |
| --- | --- |
| AC-01 | 校验仓库技能格式，检查新增和修改文档的本地链接及标题锚点，通过。 |
| AC-02 | 对照近期实现、测试和历史结果，分别补录下载与安装删除规格。PR 模板已改为引用软件规格。 |
| AC-03 | 临时工程执行 `dotnet build`。Infrastructure 引用 Core 成功，改为引用 Application 后构建报 `SMM001`。 |

完整验证执行了以下命令，Release 构建零错误，567 项测试通过，差异检查通过。

```shell
dotnet restore SteamModManager.sln
dotnet build SteamModManager.sln --configuration Release --no-restore
dotnet test --solution SteamModManager.sln --configuration Release --no-build
git diff --check
```

本次在本机验证构建检查。Windows 与 Linux 由后续三平台 CI 验证。真实 Steam 账户操作和长时间内存采样的未验证范围见各功能规格。

## 7. 下次开发提示词

> 先读 AGENTS.md，定位现有责任模块。用中文软件规格写清这一个改动的范围和可测试验收条件，复用现有入口实现。按规格审查并执行仓库检查，把结果和未验证项回填到同一份规格。
