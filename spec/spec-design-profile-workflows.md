# 背景与目标

配置导入和启动前核对包含可独立验证的业务顺序。Application 负责执行，Desktop 负责预览确认、结果提示和导航。

## 1. 范围与验收

| ID | 给定 | 当 | 则 |
| --- | --- | --- | --- |
| AC-01 | 导入预览已确认 | 重新扫描发现新的待下载项或匹配状态改变 | 返回更新后的预览，等用户再次确认再保存与排队。 |
| AC-02 | 当前导入计划已确认 | 执行导入 | 先保存，再复用已有任务或排队启用且缺失的工坊项。部分排队失败保留已保存的配置。 |
| AC-03 | 用户应用配置或准备启动 | 启动器状态不同或配置有待应用修改 | 复用写入、读回校验、保存流程。取消、缺失、读回不符和保存失败均阻止启动。 |

## 2. 责任模块与契约

Application 的配置导入用例与 WorkspaceService 复用扫描、工坊查询、下载队列和启动器端口。现有配置格式与界面入口继续使用。

## 3. 测试与结果

- 导入回归覆盖新缺失项重新确认、保存失败时不排队、复用活跃下载、跳过禁用项。
- 启动回归覆盖缺失安装、用户取消、启动器外部变更、写入后顺序校验与配置保存失败。保存失败时界面保留已核验的启动器状态并停止启动。
- 验证使用临时安装与测试替身。真实 Steam 与游戏启动器联调未执行。
- macOS arm64 按[协作规范](../CONTRIBUTING.md#4-必须完成的检查)执行还原、Release 构建、完整测试和差异检查。575 项测试通过。
