# 背景与目标

第二批扩展运行配置的诊断和导入预览。

## 1. 范围与非目标

从当前启用的 CK3 配置读取可识别的顶层特质定义与描述文件的 replace_path。文件冲突保持原入口。

## 2. 需求与验收条件

不同有效文件的相同特质键列为重名线索，列出路径和配置顺序。同路径前序文件和被后续替换目录移除的文件不进入定义索引。目录指令独立列出，解析失败或目录未覆盖时明确范围。

## 3. 责任模块与实现步骤

沿用文件扫描一次建立的目录和 ZIP 索引。Infrastructure 按顺序筛选有效脚本并解析，Core 扩展只读报告，Desktop 分组显示。无写入。

## 4. 契约、依赖与兼容性

兼容现有配置与调用方。操作绑定当前游戏工作区。

## 5. 测试策略

覆盖正向流程、数据变化、缺失、解析或请求失败及取消。按 [协作规范](../CONTRIBUTING.md#4-必须完成的检查) 执行门禁。

## 6. 审查与执行结果

自动化覆盖目录与 ZIP、不同文件的同名键、同路径前序文件排除、解析失败、禁用项和 replace_path。首版以 common/traits 直接子层的 .txt 顶层特质定义为范围。

CK3 1.20.0.4 两个隔离场景都进入主菜单。同名键位于不同文件时，日志同时记录 A、B 的测试字段。后加载 B 声明 replace_path 后只记录 B。生产扫描器对同一夹具给出两个定义来源，启用目录替换后报告一个前序路径并移除重名结果。测试用游戏已退出。

macOS arm64 还原、Release 构建、全量 603 项测试及 `git diff --check` 通过。截图、探针日志和 TRX 位于本地 `artifacts/batch2/`。
